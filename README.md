# Seen

Seen is a local Windows app that saves searchable screenshots of past computer
activity. Search for a detail you remember, then open the matching screenshot
and its extracted text.

**Measured on 24 synthetic screenshots through real Windows OCR and local embeddings:**
- 24/24 known targets in the top five hybrid results; 23/24 first (MRR 0.9792).
- 31.92 ms median / 36.66 ms p95 warm hybrid search, excluding HTTP and UI.
- 24 persisted screenshots and vectors; 929,784 bytes of temporary history/index data.

These are a small constructed-corpus check, not real-user retrieval accuracy or
production capacity. Targets and queries were fixed before searching, with no
query tuning. [Inputs and raw results](evaluation/) include rankings and per-query
latencies; the source screenshots are generated by code, not personal captures.

## How it works

Capture → detect visual changes → extract text → store locally → search → open screenshot.

The Windows worker samples the foreground window every 1–3 seconds, skips excluded
apps and unchanged frames, and uses a four-frame queue for OCR/indexing. Screenshots,
timestamps, app names, window titles and OCR text are persisted in SQLite with FTS5
BM25. Search supports keywords, local MiniLM text embeddings with FAISS HNSW, or a
weighted hybrid, plus explicit calendar filters. The browser UI runs on loopback
FastAPI and provides screenshot details, timeline, pause, exclusions and deletion.
[Architecture](ARCHITECTURE.md) explains queue bounds, recovery and privacy checks.

It **does not capture original file paths or browser URLs**. Opening a result
reopens the saved screenshot; it cannot reliably reopen the original document,
folder or page. Text embeddings do not understand screenshot pixels directly.

## Run on Windows

Use 64-bit Python 3.12 (3.11–3.13 supported) and an interactive Windows 10/11 desktop.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
# Explicit first-time model download; keyword search works without it.
.\.venv\Scripts\python.exe -m seen setup-model
.\.venv\Scripts\python.exe -m seen ui
```

Open http://127.0.0.1:8765. In a second terminal, start capture explicitly:

```powershell
.\.venv\Scripts\python.exe -m seen capture --start
```

New histories start paused. Closing the browser does not stop the capture worker;
Ctrl+C stops it. UI and capture must use the same data directory. The default is
`%USERPROFILE%\.seen`; override with `SEEN_DATA` or `--data` before the subcommand.
`powershell -ExecutionPolicy Bypass -File scripts/setup.ps1 -Python <python-executable>`
can create the environment when the Python launcher is unavailable.
`Start Seen.cmd` runs the existing launcher with a separate `demo-data` directory
and respects its saved pause state; it does not seed fixtures automatically.

OCR uses installed Windows OCR language packs, with local Tesseract fallback.
Missing OCR leaves titles searchable and reports its status. `setup-model` downloads
an open-source CPU ONNX MiniLM model once; subsequent inference is local and offline.
Missing weights produce an explicit warning; hybrid falls back to keyword search.
Run `seen reindex` after model setup to embed previously saved events.

## Reproduce the evidence

```powershell
.\.venv\Scripts\python.exe -m pytest -q
$env:SEEN_TEST_MODEL = "$env:USERPROFILE\.seen"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/evaluate_screenshots.py --model-data "$env:USERPROFILE\.seen" --output evaluation/results.json
```

The evaluation requires Windows OCR and a prepared model cache. It generates 24
labelled screenshots, passes them through the actual capture indexing worker,
checks persisted OCR/images/vectors, then evaluates the fixed queries in all three
modes. It deletes temporary history afterward. p95 uses nearest rank; startup and
HTTP rendering are excluded. Measurements are specific to this Windows run.
[Verification](VERIFICATION.md) distinguishes native capture, generated fixtures,
API/browser checks and CI scope.

For a separate six-example UI demo (provided text, not measured OCR):

```powershell
.\.venv\Scripts\python.exe -m seen --data demo-data demo --lexical-only
.\.venv\Scripts\python.exe -m seen --data demo-data ui
```

## Privacy and limitations

- History is local **plaintext**, including screenshots, OCR and vectors. There is
  no encryption, authentication or automatic retention policy. Setup downloads
  packages/model weights; captured text is not sent to an LLM or cloud service.
- Loopback binding, Host checks, cross-site rejection and mutation tokens protect
  the browser interface; they do not isolate it from other processes as the same user.
- Pause, exclusions and deletion invalidate queued frames. Defaults exclude common
  password managers and Codex; Seen and credential/lock-screen windows are skipped.
- Capture sees the visible foreground rectangle, including overlapping notifications;
  protected content may be black. Small edits can evade change detection, and a full
  queue drops samples. It does not capture minimized/background tabs, audio or video.
- Calendar phrases support dates such as today, yesterday and last week; arbitrary
  before/after activity relationships are not reconstructed.
- The native capture smoke test was brief. Long-session throughput, diverse personal
  retrieval quality and disk growth have not been measured. Synthetic results do not
  establish those properties.
